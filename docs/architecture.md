# 架构与执行规则

## 模块化单体 + 独立回测进程

Web 使用原生 HTML/CSS/JavaScript，静态资源由 FastAPI 提供，无 Node 构建依赖。后端与策略均为 Python。一个 API 进程管理最多两个工作进程；每次回测使用一个独立 Python 进程。Linux 下以文件锁限制同一任务目录只能由一个 API 实例管理。

- `models.py`：不可变行情、成交与费用模型，以及内部订单/持仓对象。
- `account.py`：资产状态的唯一维护者，负责预留、释放、成交记账及估值。
- `matching.py`：订单状态、下一根开盘撮合、撤单及执行报告。
- `engine.py`：模拟时间、历史数据可见性、回调与报告分发。
- `data.py`：SDK 适配与合成数据。不同供应商的字段语义仅在此映射。
- `jobs.py` / `worker.py`：任务快照、独立进程、并发限制、取消与超时。
- `api.py` / `static/`：网页与任务接口。

核心可以独立导入，不要求启动 Web；策略上下文不依赖 HTTP。

## 模拟时间

内部使用 Asia/Shanghai 有时区时间。每根 K 线有明确 `start` 与 `end`。

1. 加载数据，只有早于回测开始盘前时点的历史数据进入初始窗口，执行 `init`。
2. 交易日 09:00：结转可卖持仓，执行 `before_trading`。
3. 按时间推进。相同时间戳先发布已经结束的各频率行情，再调用驱动频率的 `handle_bar`；随后处理下一根 K 线开盘撮合。
4. 撮合完成后先记账，再分发订单和成交回报；回报中新产生的订单不能加入本次已快照的撮合批次。
5. 交易日 15:01：执行 `after_trading` 并记录每日账户净值。
6. 回测结束时未成交订单到期并释放预留，发出回报，执行 `on_finish`。

日线覆盖 09:30–15:00；分钟行情按配置规范化为开始与结束时间。午休及隔夜由实际时间序列自然跳过。盘前、盘后下单同样等待下一个可参与的开盘事件。最后一根结束后下单不会虚构未来成交。

策略只通过 `history` 获取已完成 Bar，当前形成中的 Bar 的高低收不对策略开放。分钟回测可查询同日已完成的日线，但在 15:00 前不会获得该日完整日线。

## 交易、账户与费用

策略下单后先校验参数和账户，再冻结资金或可卖数量。市场委托的预留使用当前已知参考价格与预估费用，限价委托使用限价。未知参考价时，可提供限价；不得读取未来开盘价作为预留依据。

下一次对应股票开盘事件按订单提交顺序处理。买单须满足开盘价不高于限价，卖单相反。买入遇开盘价达到涨停价、卖出遇开盘价达到跌停价，采取保守不成交规则；其他方向不因同一限制被阻止。默认不模拟成交量与排队。

跳空造成实际金额加费用超过该订单可使用资金时拒绝订单并释放冻结；不能使用其他订单已冻结的资金。当前一次全额成交，部分成交留待后续设计。订单为 GTC，在不符合成交条件时继续等待，回测结束到期。

金额使用 Decimal，现金、费用和记账金额保留分，四舍五入。买入费用计入持仓成本；卖出按剩余平均成本结转，盈亏含费用。账户维持以下等式：

- 总资产 = 现金余额 + 持仓市值。
- 现金余额 = 可用资金 + 冻结资金。
- 总盈亏 = 已实现盈亏 + 未实现盈亏（无外部现金流场景）。

买入当日不能卖出，下一交易日将持仓转为可卖。冻结卖出数量从可卖量扣除。每个成交编号只记账一次。策略得到账户和订单的副本，不能通过普通接口直接修改内部状态。

## 任务与可复查性

每次任务目录包含策略源码、完整配置、进度、结果或错误、标准输出日志。策略修改不会影响旧任务快照。结果保留来源、时间标签选择和跳过记录数，但尚未固定数据服务版本，不能保证将来重新下载的数据逐字相同。

取消和超时终止整个工作进程组；正常关闭服务会取消运行中任务。重启后发现运行中记录会标为 interrupted，不恢复执行。强制杀死 API 的异常场景尚不保证清理此前工作进程，生产部署应增加服务级进程组托管。

本地进程隔离不是安全沙箱。仅运行可信代码。API 限定本机 Host，写请求校验自定义请求头与 Origin，默认不向外网绑定。
